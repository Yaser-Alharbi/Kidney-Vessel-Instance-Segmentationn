Teaching AI to Find Blood Vessels in Kidney Tissue

...even when the stain colour changes from lab to lab

Pathology labs stain tissue slightly differently, and a model trained on one lab's colours can stumble on another's. I trained the same U-Net 4 ways, changing only how it handles stain colour, and repeated each recipe with 20 different random seeds. Randomly varying the stain during training gave the most accurate vessel outlines on slides the model had never seen.

The problem

Same tissue, different colours

Kidney biopsies are cut into thin slices and stained so that structures show up under a microscope. The tissue here uses PAS (periodic acid–Schiff) with a haematoxylin counterstain: purple-blue for cell nuclei, magenta-pink for membranes and connective tissue. Finding the blood vessels is a step towards mapping the kidney's vasculature, which the HuBMAP project is building a reference atlas of.

The catch is that stain colour is not standardised. Stain batch, staining time, slice thickness and scanner all shift the colours, so the same structure can look noticeably different from one lab, or one slide, to the next. A model that has only seen one colour profile tends to learn the colours instead of the shapes, and loses accuracy on new slides. This study tests four ways of dealing with that.

The showcase tile with both stains scaled in optical-density space, the same operation stain jitter uses during training. A real lab-to-lab shift looks much like this.

How can a computer separate the two stains?

Each stain absorbs light in its own characteristic way. Converting RGB to optical density (how much light is absorbed) makes the stains add up linearly, and a fixed stain matrix (Ruifrok & Johnston, 2001) then splits every pixel into a haematoxylin amount (H), an eosin-like amount (E) and a third residual channel. This is called colour deconvolution. Both stain-aware recipes below work in this space.

Code: HED matrix · Macenko normalisation

The data

Slides, tiles and an honest split

The data comes from the HuBMAP Hacking the Human Vasculature Kaggle challenge: whole-slide images (WSIs) of human kidney cut into 512 × 512 tiles. 1,633 tiles carry polygon annotations, with 16,054 blood-vessel outlines in total. Only blood vessels are used here; glomeruli and “unsure” regions are ignored.

Vessels are small: on average they cover 4.5% of a tile (median 3.2%). That imbalance shapes the loss function and the metric.

Why split by slide, not by tile? Tiles from one slide share its stain and its patient. If tiles from the same slide sat in both training and test, the model could score well by recognising the slide, which says nothing about new slides. Every split here uses different slides, and the split code checks they never overlap. The test slides come from a different part of the dataset whose labels were generated automatically, so they are noisier than the expert labels.

Why the scores look low

A Dice around 0.204 sounds poor, but three things push it down, and none of them changes which recipe wins. The training set is 270 tiles from 1 slide. Vessels are thin and small, and Dice is harsh on small objects: missing a vessel's edge by a few pixels costs a large share of it. And the test labels are auto-generated, so some “misses” are label errors. The study is built to compare recipes against each other under identical conditions, not to chase a leaderboard score.

Training setup, and why

  • U-Net with a ResNet-34 encoder The standard architecture for medical segmentation. The encoder starts from ImageNet weights, which helps with only 270 training tiles.
  • Dice + BCE loss Vessels are a small share of pixels, so plain per-pixel loss would reward predicting “no vessel”. The Dice term matches the evaluation metric; the BCE term keeps gradients smooth early in training. Code
  • AdamW, learning rate 0.0001, weight decay 0.0001, cosine schedule A conventional, well-behaved setup for fine-tuning a pretrained encoder; the learning rate decays smoothly to zero. Code
  • Up to 30 epochs, early stop after 4 Training stops once validation Dice has not improved for 4 epochs, and the best epoch's weights are kept. This limits overfitting on a small training set.
  • Batch 16, tiles 512 × 512 Full tiles at native resolution, so thin vessels are not blurred away by resizing.
  • 20 seeds per recipe For statistical power. The comparison uses a paired test across runs, and with only 3 runs per recipe the smallest p it can ever produce is 0.125, even if one recipe wins every time. With 20 runs that floor drops to 9.5e-07. In the results, the run-to-run spread of the baseline (std 0.024 on test) turned out to be about as large as the gap between recipes (+0.025), so a single run could easily have pointed the wrong way.

All 80 runs took 2.8 hours of GPU time in total.

Stain jitter (HED jitter)

Randomly makes each stain a little stronger or weaker for every training tile, so the model never sees exactly the same colours twice.

How it works

The tile is converted to optical density and split into H, E and residual channels by colour deconvolution. Each channel is multiplied by a random factor in 1 ± σ and shifted by a random offset in ±σ, then converted back to RGB. With σ = 0.05, applied to 80.0% of training tiles.

Details

Matrix: Ruifrok & Johnston (2001). HEDJitter · where the recipe sets σ and p

Stain normalisation (Macenko)

Estimates each tile's own two stain colours, then repaints the tile as if it had been stained with one fixed reference.

How it works

Background pixels are dropped and the rest are converted to optical density. The two main directions of variation (from an SVD) span a plane; the extreme angles in that plane give the tile's two stain vectors. Concentrations are rescaled so their upper percentile matches the reference, then recombined with the reference stain matrix. Degenerate tiles are returned unchanged.

Details

Method: Macenko et al. (2009). The reference stain matrix comes from H&E, which is exactly what the second hypothesis questions for PAS. MacenkoNormalize

U-Net with a ResNet-34 encoder

An encoder shrinks the tile into increasingly abstract features; a decoder expands them back to full resolution to label every pixel.

How it works

Skip connections carry fine detail from the encoder straight to the decoder, which matters for thin structures like vessels. The output is one score per pixel; a sigmoid above 0.5 means “vessel”.

Details

segmentation-models-pytorch Unet(resnet34), ImageNet weights, single output channel. Code

Bootstrap CI and Wilcoxon test

Two ways of asking whether a difference between recipes is real or just luck.

How it works

Bootstrap: resample the scores with replacement 2,000 times and take the middle 95% of the resampled means as a confidence interval.

Wilcoxon signed-rank: pair each stain-jitter run with the baseline run that used the same seed, then ask whether the differences lean positive. It is paired because both runs share the same random start, non-parametric because Dice is not normally distributed, and one-sided because each hypothesis predicts a direction.

Details

bootstrap_dice · paired_wilcoxon_dice (scipy)

What the 80 runs say

All headline numbers below are across runs: each recipe's mean Dice over its 20 training runs, tested with a paired one-sided Wilcoxon across those runs.

Limitations and next steps

What this does not show

  1. Noisy test labels. The test slides have auto-generated labels. They are fine for ranking recipes, but the absolute scores understate true accuracy.
  2. One training slide. All 270 training tiles come from 1 slide. More slides, and more labs, would test the stain question far harder.
  3. Validation picks the best epoch. Validation scores are therefore slightly optimistic; the test slides give the honest comparison.
  4. The stress test uses one tile. It illustrates the behaviour; the across-run statistics are the evidence.
  5. The Macenko reference was not fitted to PAS. A PAS-specific reference might change the second result. That is the natural next experiment, along with training the combined recipe on normalised colours so train and test match.

Glossary

Terms used on this page

Dice score
Overlap between the predicted vessels and the labelled vessels: twice the shared area divided by the total area of both. It runs from zero (no overlap) to one (perfect match).
IoU
Intersection over union: the shared area divided by the area covered by either. Stricter than Dice, and always lower for the same prediction.
U-Net
A neural network for image segmentation. It compresses the image into features, then expands them back to label every pixel, with shortcuts that keep fine detail.
Seed
The number that fixes all the randomness in a training run (initial weights, data order, augmentation). Different seeds give slightly different models from identical settings.
Wilcoxon signed-rank test
A test on paired differences that does not assume a normal distribution. Here it pairs runs that share a seed and asks whether one recipe is consistently better.
p-value
How likely a result at least this consistent would be if there were no real difference. Small values mean luck is an unlikely explanation.
Confidence interval
A range that plausibly contains the true mean, given the spread of the data.
Bootstrap
Estimating uncertainty by resampling the observed data many times with replacement and seeing how much the result moves.
WSI
Whole-slide image: a scan of an entire microscope slide, often tens of thousands of pixels across.
Tile
A small square crop of a whole-slide image, the unit the model sees.
Optical density
How much light the tissue absorbs at each pixel. Stains add up linearly in this space, which makes separating them possible.
Colour deconvolution
Splitting each pixel's colour into the amount of each stain, using the known colour of each stain.
Loss function
The quantity training tries to minimise. Dice loss rewards overlap directly; BCE (binary cross-entropy) scores each pixel separately.
